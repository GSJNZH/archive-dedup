# 素材归档去重工具

![Platform](https://img.shields.io/badge/platform-Windows%2011-0078D6)
![Python](https://img.shields.io/badge/python-3.10%2B-3776AB)
![Dependencies](https://img.shields.io/badge/dependencies-standard%20library-success)
![License](https://img.shields.io/badge/license-MIT-green)

按内容指纹对比「剪辑归档文件夹」和「原素材文件夹」，把原素材中**未被归档覆盖**的文件，按原相对目录复制/移动到「未归档补充」目录。上传百度网盘时只需上传「归档文件夹 + 未归档补充」，避免同一素材在两个路径下各占一份配额。

- 平台：Windows 11
- 运行环境：Python 3.10+（已在 3.12.14 实测），仅标准库
- 依赖：`tkinter`（GUI 需要，Windows 官方 Python 自带）
- 默认不删除、不改动原素材

## 主要功能

- 三档比对：极速（大小+mtime）、快速（头尾 64KB 采样 MD5）、精确（全量 MD5）。
- GUI 和 CLI 共用一套核心逻辑，CLI 支持 `--dry-run`、`--json` 和退出码。
- 复制使用 `.part` 临时文件 + 原子改名；复制前做磁盘空间预检。
- 支持复制和同盘移动；默认复制，移动前二次确认。
- 运行结束后可自动复查，逐文件核对未归档文件是否都在输出目录中。
- 复查通过后在输出目录生成 `复查报告.txt`，包含项目名、大小、逐文件指纹和集合 SHA256。
- 选好原素材后，默认输出目录为 `<原素材>\09_04-未使用画面`。
- 自测脚本覆盖比对、复制、移动、复查、报告和异常场景。

---

## 1. 背景

剪辑完成后，素材短期还会用，长期基本不用，需要整体存到百度网盘。

百度网盘的“秒传/服务器去重”只节省上传时间，**不节省个人账户配额**：同一个文件出现在两个文件夹路径下，配额仍按两份计算。

所以正确做法不是依赖网盘去重，而是本地先筛掉重复：

- **归档文件夹**：自包含工程 + 已打包素材；
- **原素材文件夹**：原始素材；
- 只把原素材中“归档没覆盖到的独有文件”单独拿出来，随归档一起上传。

工具不会自动删除原素材。删除原素材前，必须先验证归档文件夹能独立打开工程、没有脱机素材。

---

## 2. 工作原理

1. 扫描归档文件夹，为每个文件生成比对键，建立 `key_set`。
2. 遍历原素材文件夹，为每个文件生成同样的键：
   - 键在 `key_set` 中 → 已归档，跳过；
   - 不在 → 未归档，加入待处理清单。
3. 把未归档文件按**相对原素材文件夹**的路径输出到「未归档补充」目录，保留 `素材123/子目录/文件` 的结构。
4. 上传网盘时只传：归档文件夹 + 未归档补充输出目录。

```
原素材/                          未归档补充/
├─ 素材A/                        ├─ 素材B/
│  ├─ clip01.mp4  (已归档)       │  └─ clip02.mp4  (独有)
│  └─ clip02.mp4  (已归档)       └─ 素材C/
└─ 素材B/                           └─ clip03.mp4  (独有)
   └─ clip02.mp4  (独有)
```

空文件夹不会被保留：工具只遍历文件、再由文件路径反推目录。需要保留空目录骨架时得额外加逻辑。

## 3. 文件清单

| 文件 | 用途 |
| --- | --- |
| `archive_dedup.py` | GUI 主程序（tkinter），也是核心逻辑所在 |
| `archive_dedup_cli.py` | 无界面 CLI 封装，复用 `worker()`，供计划任务/批处理/无界面环境调用 |
| `selftest.py` | 自测脚本：临时目录跑三种模式、复制、移动、排除规则 |
| `archive_dedup_config.json` | GUI 自动生成的配置（路径、模式、并发），首次运行后出现 |

`archive_dedup_cli.py` 直接 `import archive_dedup`，不复制核心逻辑；改比对/复制规则只需改 `archive_dedup.py`。

## 4. GUI 使用

```bat
python archive_dedup.py
```

界面分三块：

1. **指定目录**：归档文件夹、原素材文件夹、未归档补充输出目录；每行有“浏览...”和“打开”。
2. **选项与执行**：比对模式、复制方式、并发数、试运行、详细日志、完成后自动复查、开始/取消/复查输出。
3. **实时日志**：逐文件输出序号、文件名、大小、指纹、已归档/未归档、累计大小、速度、剩余时间；进度条和状态栏同步。

选好原素材文件夹后，“未归档补充输出目录”会自动填成：

```text
<原素材文件夹>\09_04-未使用画面
```

可以再手动改成别的目录。勾选“完成后自动复查”（默认勾选）时，复制/移动结束后会自动复查，不需要再点一次按钮。

推荐顺序：

1. 勾选“试运行”，模式选“快速”，先看未归档清单是否合理。
2. 取消“试运行”，复制方式按需选“复制”或“同盘移动”，执行。
3. 执行结束后自动复查；通过后输出目录会生成 `复查报告.txt`。也可以随时点“复查输出”手动复查。
4. 完成后只上传「归档文件夹」+「未归档补充」。
5. 网盘里如果之前已传过原素材文件夹，要删掉旧副本并清空回收站，否则配额仍按两份算。

GUI 会把上次的路径和选项写入 `archive_dedup_config.json`（脚本目录不可写时落到 `%APPDATA%`）。

## 5. CLI 使用

```bat
python archive_dedup_cli.py <归档目录> <原素材目录> <输出目录> [选项]
```

先试运行，确认清单：

```bat
python archive_dedup_cli.py "D:\Archive\项目A" "D:\Footage\项目A" "D:\未归档补充\项目A" --dry-run
```

确认后执行复制（默认快速模式、单线程）：

```bat
python archive_dedup_cli.py "D:\Archive\项目A" "D:\Footage\项目A" "D:\未归档补充\项目A"
```

精确复核 + 4 线程：

```bat
python archive_dedup_cli.py "D:\Archive\项目A" "D:\Footage\项目A" "D:\未归档补充\项目A" --mode exact --workers 4
```

同盘移动（会从原素材移除未归档文件，非交互环境必须加 `--yes`）：

```bat
python archive_dedup_cli.py "D:\Archive\项目A" "D:\Footage\项目A" "D:\未归档补充\项目A" --copy-mode move --yes
```

### 选项

| 选项 | 说明 |
| --- | --- |
| `--mode turbo\|fast\|exact` | 比对模式，默认 `fast` |
| `--copy-mode copy\|move` | 默认 `copy`；`move` 会移除原素材中的未归档文件 |
| `--workers N` | 并发线程 1–32，默认 1；机械盘建议 1，SSD 可试 2–4 |
| `--dry-run` | 只扫描比对并列出未归档文件，不复制/移动，也不创建输出目录 |
| `--verify` | 复查模式：检查未归档文件是否都在输出目录中且内容一致，不复制；不能与 `--dry-run` 同用 |
| `--verbose` | 逐文件日志；默认只输出阶段摘要（试运行仍会列出全部独有文件） |
| `--json` | stdout 只输出 JSON 摘要，日志走 stderr |
| `--progress` | 每秒向 stderr 输出一次进度 |
| `--yes` | 同盘移动时跳过交互确认 |
| `--force` | 输出目录非空时仍然继续（可能混入旧文件） |

### `--json` 输出示例

```json
{
  "ok": true,
  "cancelled": false,
  "dry_run": false,
  "mode": "fast",
  "copy_mode": "copy",
  "workers": 4,
  "elapsed_seconds": 12.345,
  "archived": 1200,
  "unique": 37,
  "copied": 37,
  "failed": 0,
  "output": "D:\\未归档补充\\项目A"
}
```

### 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 成功（含试运行） |
| 1 | 用户在确认处取消 |
| 2 | 参数或路径不合法 |
| 3 | 运行期错误 |
| 4 | 部分文件处理失败（其余成功） |
| 5 | 复查未通过（缺失/不一致/多余/`.part`/读取失败） |
| 130 | 被 Ctrl+C 中断 |

### 安全校验

CLI 在执行前会检查：

- 归档、原素材目录存在且不是同一个；
- 输出目录不能是归档目录、不能在归档目录内部、不能包含归档目录、不能等于原素材目录；
- 输出目录非空时必须显式加 `--force`；
- `move` 且非试运行时必须交互确认或加 `--yes`。

输出目录位于原素材内部时是允许的，扫描会自动排除输出目录，避免自己复制自己。

### 复查输出

**复查不要求先完成一次复制/移动**，随时可以对任意输出目录做检查。点 GUI 的“复查输出”，或运行：

```bat
python archive_dedup_cli.py "D:\Archive\项目A" "D:\Footage\项目A" "D:\未归档补充\项目A" --verify
```

复查优先使用输出目录里的 `_archive_dedup_manifest.json`（复制/移动开始时会自动写入），因此**同盘移动后原素材里已经没有未归档文件，也能复查**。清单会记录每个应处理文件的相对路径、大小和指纹。

没有清单时，复查会按当前原素材重新比对；如果原素材中也已没有未归档文件，则无法判断移动完整性，会报“缺少复查清单”并退出 5。

复查会重新扫描归档和原素材，找出所有“未归档”文件，再在输出目录按相对路径逐个比对：

- **缺失**：原素材有、输出没有；
- **内容不一致**：路径存在但大小/指纹不同；
- **多余**：输出里有、但不属于本次未归档集合；
- **`.part` 残留**：上次复制中断留下的临时文件；
- **读取失败**：扫描/哈希阶段有文件读不了，无法确认，按未通过处理。

全部一致时退出码为 0；有任何缺失/不一致/多余/`.part`/读取失败时为 5。需要更强校验时加 `--mode exact`（全量 MD5，慢但最准；清单用的是生成时的模式，复查会按清单模式校验）。

复查是严格模式：输出目录里多出旧文件也算未通过，避免把上次的残留一起上传。输出目录不存在或为空也可以复查：会按空目录核对，所有未归档文件记为缺失并返回 5，**不会创建目录**。`--verify` 不能与 `--dry-run` 同用。

复查通过后，会在输出目录生成 `复查报告.txt`（UTF-8 BOM，记事本直接可读），内容包括：

- 项目名称、复查时间、复查结果；
- 归档目录、原素材目录、输出目录；
- 归档/源文件/已归档/未归档/输出匹配的数量与总大小；
- 每个未归档文件的相对路径、大小、完整指纹；
- 整个输出集合的 SHA256 汇总指纹；
- 本次使用的比对模式和指纹算法说明。

报告文件在后续复查中会被自动忽略，不会算作“多余文件”。没有未归档文件时不生成报告。重新执行复制/移动时会先清除旧报告，避免本次复查失败后仍留着上一次的“通过”结果。GUI 勾选“完成后自动复查”时，复制/移动结束后会自动执行复查并生成报告。

`--json` 输出示例：

```json
{
  "ok": true,
  "verify": true,
  "cancelled": false,
  "mode": "fast",
  "elapsed_seconds": 0.13,
  "archived": 57,
  "unused": 273,
  "verified": 273,
  "missing": 0,
  "mismatch": 0,
  "extra": 0,
  "part": 0,
  "errors": 0,
  "no_manifest": 0,
  "unused_bytes": 50065975610,
  "report": "D:\\未归档补充\\项目A\\复查报告.txt",
  "output": "D:\\未归档补充\\项目A"
}
```

## 6. 比对模式

| 模式 | 比对键 | 读取量 | 适用 |
| --- | --- | --- | --- |
| 极速 `turbo` | `(文件大小, mtime_ns)` | 不读内容 | 归档由复制生成、保留修改时间 |
| 快速 `fast`（默认） | `(大小, 头 64KB MD5, 尾 64KB MD5)` | 每文件约 128KB | 绝大多数视频素材 |
| 精确 `exact` | `(大小, 全量 MD5)` | 全文件 | 关键项目最终复核 |

快速模式不是数学证明，但对“判断归档里有没有这个素材”足够。不放心时可以先用快速模式跑清单，再对关键文件用精确模式复核。

极速模式依赖归档保留原文件 mtime；转码/重新封装的代理文件 mtime 会变，应使用快速模式。

## 7. 复制方式与性能

- **复制（安全）**：Windows 下优先调用内核 `CopyFileW`（支持长路径），复制后恢复修改时间；失败回退 `shutil.copy2`。先写 `目标.part`，成功后再原子改名，中断不会留下最终文件名的半文件。
- **同盘移动（瞬间）**：输出目录与原素材同一磁盘时用 `os.rename`，不产生读写；会从原素材移除未归档文件，默认关闭，执行前二次确认；跨盘自动退化为复制。
- **空间预检**：复制前检查输出卷可用空间，不足直接中止，不会抄到一半才失败。
- **同盘提示**：复制模式下若输出与原素材同盘，日志会提示可改用移动，但不会自动切换。
- **失败统计**：逐文件捕获异常，结束时报成功/失败数量；CLI 有失败时退出码为 4。
- **自动复查**：GUI 默认在复制/移动结束后自动复查；通过后生成 `复查报告.txt`，失败则在结果框里列出缺失/不一致数量。
- **并发复制**：可选 1/2/4/8 线程；机械盘建议 1，SSD 可试 2–4。
- **日志节流**：worker 批量上报日志，GUI 每轮最多处理 600 条，避免刷日志卡界面。

慢的常见根因：全量哈希读盘、Python 逐块复制、Defender 实时扫描、机械盘读写交替。当前版本已针对前三项优化。

## 8. 安全边界

- 工具只读、只复制；不会自动删除原素材。
- “同盘移动”会移除原素材中的未归档文件，默认不选，且有二次确认。
- 建议先验证归档文件夹能独立打开工程、无脱机素材，再手动处理原素材中的重复文件。
- 输出目录若在原素材内部，扫描时会自动排除输出目录。
- 复制使用 `.part` 临时文件 + 原子改名；正常取消/失败会清理，进程被杀时可能留下 `.part`，重跑会自动覆盖。
- 复制模式原素材不受影响，重跑即可。
- 输出目录不能是归档目录、不能在归档内部、不能包含归档目录、不能等于原素材；GUI 在启动前校验。
- 输出目录不存在时 GUI 会先确认再新建，避免路径手误建出第二份。
- 输出目录已存在且非空时，GUI 会提示；CLI 默认拒绝，需 `--force`。

## 9. 网盘配额注意

工具的产物是「归档文件夹 + 未归档补充」两份。上传后：

- 不要再把完整「原素材文件夹」也传上去；
- 如果之前已经传过，删除网盘里的旧副本并**清空回收站**，否则配额仍按两份计算；
- 秒传只省时间，不省配额。

## 10. 已知限制

- GUI 是 tkinter，不适合完全无头环境；无头场景用 `archive_dedup_cli.py`。
- 空文件夹不会保留。
- 极速模式依赖 mtime，转码/重新封装后不可靠。
- 快速模式是采样哈希，极端情况下可能把不同文件判成同一个（概率极低）；关键项目用精确模式复核。
- 日志上限 5000 行，超出裁掉最早 2000 行，防止界面变卡。
- 取消复制只能在文件之间生效，正在复制的大文件会先复制完。
- 长路径依赖 Windows 长路径支持；`CopyFileW` 已加 `\\?\` 前缀，但 `os.walk` 仍可能受系统策略限制。

## 11. 故障排查

```bat
python -m py_compile archive_dedup.py archive_dedup_cli.py selftest.py
```

- **`ModuleNotFoundError: tkinter`**：安装官方 Python 时勾选 tcl/tk；或改用 CLI（仍需能 import tkinter，因为 CLI 复用同一模块）。
- **复制很慢**：换 `--mode turbo` 先出清单；机械盘把 `--workers` 设为 1；把归档/原素材目录加入 Defender 排除项。
- **移动失败“目标已存在”**：输出目录里有同名旧文件；换空目录或先清理。
- **中文路径乱码**：在终端执行 `chcp 65001`，或设置 `PYTHONUTF8=1`。
- **GUI 取消后按钮不恢复**：新版已修复取消时未回传完成事件的问题。

## 12. 自测

```bat
python selftest.py
```

自测在 `_selftest_tmp/` 下构造临时目录，覆盖：

- 快速 / 极速 / 精确三种比对模式；
- 试运行不落盘；
- 复制保留相对路径、空文件和修改时间；
- 同盘移动后原素材只剩已归档文件；
- 输出目录位于原素材内部时被排除；
- 输出目录非空时的保护；
- 取消时 worker 回传 `cancelled`，不复制文件；
- 输出在归档内部 / 等于原素材 / 包含归档时被拒绝；
- `.part` 原子复制、覆盖旧文件、保留 mtime、无残留；
- 单文件失败时统计 `failed`，其余文件继续；
- 空间不足时中止且不创建输出目录；
- 同盘提示出现在日志中；
- 复查通过、缺失、内容不一致、多余文件、`.part` 残留、读取失败、移动后复查/清单、未运行复制也能复查、输出目录在原素材内部、TXT 报告内容（含移动后的源文件统计）和 `--verify` 参数守卫。

测试结束会删除临时目录，全部通过时退出码为 0。项目在 Python 3.12.14 下 115 项断言全部通过。

- 修复取消后 GUI 卡在“运行中”的问题：取消时 worker 回传 `{"cancelled": true}`，GUI 恢复按钮并提示。
- 复制阶段取消时返回已成功数量，不再误报“全部完成”。
- 输出路径校验：拒绝“在归档内部 / 包含归档 / 等于原素材”；目录不存在时先确认再新建。
- 复制改为 `.part` 临时文件 + 原子改名，中断不再留下最终文件名的半文件。
- 复制前做磁盘空间预检；同盘复制时日志提示可改用移动。
- 失败统计：GUI 显示失败数，CLI 新增 `failed` 字段和退出码 4。
- 新增复查功能：GUI“复查输出”按钮 + CLI `--verify`，报告缺失/不一致/多余/`.part`/读取失败，未通过退出码 5。
- 复查不要求先完成复制/移动，也不要求输出目录已存在；空目录/不存在目录按缺失处理，不会创建目录。
- 复制/移动开始时写 `_archive_dedup_manifest.json`，复查优先按清单核对，移动模式也能查完整性。
- 新增“完成后自动复查”（默认勾选）：复制/移动结束后自动执行复查，无需手动再点。
- 复查通过后在输出目录生成 `复查报告.txt`，包含项目名、时间、目录、统计、逐文件大小和完整指纹。
- 选好原素材后，输出目录默认填 `<原素材>\09_04-未使用画面`。
- GUI 选择目录后统一用 `os.path.normpath` 规范为 Windows 反斜杠，修复默认输出出现 `D:/...\09_04` 混合斜杠的问题。
- 路径比较统一用 `normcase`，避免 Windows 大小写导致输出目录排除失效。
- 新增 `selftest.py`。

核心比对逻辑未改。
